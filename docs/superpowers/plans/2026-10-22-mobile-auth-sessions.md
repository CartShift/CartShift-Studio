Goal: complete the user's persistent provider authentication and Issue117 using existing Docker/CartShift. User explicitly authorizes autonomous implementation, merge and deployment; request only real browser/MFA approvals. No production Ensemblis migration.

Architecture: owner-only four MCP tools and a dedicated authenticated outbound sessions endpoint; Python worker version3 with one guardian broker process started BEFORE threads/stateless jobs. No public ports/new cloud services.

## Frozen protocol (backend and worker implement independently)
Endpoint POST /api/cartshift-mcp/sandbox/sessions/worker. Existing dedicated Bearer worker token, strict bounded JSON. Body {action:"sync",version:3,epoch:UUID,session:Snapshot|null}. First sync registers a boot epoch; epoch change expires any previous active session, erases pending input. First-sync registration is not allowed to race another live epoch; prior epoch heartbeat must be stale or explicit same-owner restart handoff (root coordinates lifecycle).
Response {session:Desired|null}. Desired {session_id,provider,cwd,ttl_seconds,idle_timeout_seconds,expires_at(epoch milliseconds),status,pending_input:null|{input_id,input_type,input}}. status pending/running/waiting_for_input/stop_requested or terminal. Snapshot {session_id,status,output,output_start,cursor,exit_code:null|int,reason:null|string,ack_input_id:null|string}. output is a REDACTED tail <=24000 UTF8bytes. cursor/output_start are Unicode code-point counts; cursor-output_start equals codepoint length(output). Backend must independently redact again. Duplicate snapshots/inputs are idempotent; pending input erased only when matching ack arrives. Worker deduplicates input_id; lost HTTPS response must not resend verification input. Backend read output only since cursor, flags gaps/truncation. No raw input in public results or audit.

MCP start {provider: enum supabase/github/vercel/firebase/shopify,cwd default /workspace,ttl_seconds60..900 default600,idle_timeout_seconds30..300 default180}. One active session per owner via Firestore transaction; fresh version3/epoch handshake required. Read {session_id,cursor>=0 default0}. Send {session_id,input_type:confirm|verification_code,input:string<=512}; confirm only empty/y/yes/n/no, Supabase code exactly8hex, Firebase code /^4\/[A-Za-z0-9._~-]+$/; other providers do not accept pasted verification tokens. Reject known PAT/access/JWT formats; never allow newlines or raw passwords. Stop {session_id}. All methods ownerUid==SANDBOX_OWNER_UID plus proper existing read/write tool scopes. TTL/idle expiry must enforce even when owner is disconnected. Lifecycle audit metadata only.

Session endpoint maintains worker control doc and session docs in sandbox_auth_sessions. Sessions purgeAt Timestamp expiresAt+1h (TTL config only for this new field). Control owns activeSessionId+epoch+lastSeenAt/version; use constant bounded reads and cap1. Session ownership never transfers. Idle deadline extends on accepted input, not repeated read. Old worker state API remains compatible; modify heartbeat route to allow optional worker_version2|3 with old2 default; recordSandboxHeartbeat(busy,version=2). New worker uses3 and getSandboxStatus adds interactive capability only with fresh sessions handshake.

Worker guardian uses PTY ECHO/ECHONL disabled, clean child environment, fixed bash --noprofile --norc /workspace/scripts/devctl PROVIDER login. No arbitrary commands/argv. Exact existing UID/Linux/aarch64/hostname/workspace identity remains mandatory. Session provider homes persistent0700. Treat same UID as trusted boundary. Guardian process must be baseline child before stateless execute() starts so existing subreaper cleanup cannot kill auth sessions. One guardian owns all interactive descendants, uses subreaper, killpg and reaping; handles stop/idle/TTL/pipeEOF/parent death. Persist ONLY nonsecret PID/start-tick cleanup metadata under private /tmp dir for verified stale-group cleanup after crash/restart; no raw output/input disk spool. Redaction must handle ANSI/split secret strings and echoes; output cap/stream flood bound. Prompts/auth links retained. No worker token in PTY env/args. One sessions sync thread with short active interval and30s idle backoff; main command flow unchanged, sessions continue during long stateless jobs. Module ownership: scripts/sandbox_pty.py and worker integration. Root extends existing Windows bootstrap to hash TWO owner-held source files and preload helper from verified memory before executing worker; no writable imports, no disabled hash checks.
